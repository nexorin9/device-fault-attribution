# 视觉目标卡 · 医疗设备故障归因系统

> 交付形态：**桌面常驻小工具 = 常驻进程（托盘计数 + 轮询 + 状态落库）+ 窗口（簇卡片 / 批量确认 / 就绪三态）**。
> 本运行环境无图像生成能力，故只保留结构化视觉目标卡，**不伪造图片**。真实运行截图见 `docs/screenshots/`。

## 画面类型

| 状态 | 画面类型 |
|---|---|
| 起始态 | 桌面窗口（单窗口两栏） |
| 首个可用瞬间 | 桌面窗口（簇卡片 + 核查步骤列表） |
| 成形态 | 桌面窗口（簇列表 + 今日动作区）+ 系统托盘项计数 |

---

## ① 起始态（刚装好，还没有故障工单进来）

桌面窗口开着，左栏是**设备注册表**（表头 + 3 行样例设备：监护仪 / 输注泵 / 呼吸机，含型号、固件、到货批次、所在科室），右栏是空的**故障簇列表**（空态文案：「暂无待确认簇」，并给出「先设置工单源地址」的引导入口）；窗口底部状态栏显示「工单源：未连接（请设置 `WORKORDER_BASE_URL`）」。系统托盘图标安静待命，托盘项标题无计数。

画面气质：像一台刚插上电的仪器 —— 安静、有序、还没有读数。

---

## ② 首个可用瞬间（新故障工单进来，自动聚成一个簇）

托盘项标题变为「2 条待处理」，窗口顶部出现一条横幅：「新增 1 张故障工单 · 疑似并入簇 C-007」。左栏设备注册表里对应 3 台设备高亮；右栏主区域出现一张**簇卡片**：

- 卡片标题：「簇 C-007 · 疑似同源 · 3 台设备 · 观察中」
- 成员表格（等宽数字、右对齐）：设备号 / 型号 / 固件 / 到货批次 / 科室 / 故障描述
- 下方是**「核查步骤（按优先级）」**列表：
  1. 核对 3 台设备固件版本是否均为 `v2.1.4`
  2. 检查同批次电源板供电采样
  3. 抽检批次内第 4 台未报障设备
- 卡片底部两个按钮：**「确认并批量开单」**（主按钮）/ **「仅存观察」**（次按钮）

这是全流程第一个让用户「哦，它真的看懂了」的画面。

---

## ③ 成形态（多簇并存、已开单、可带走）

右栏主区域变成**簇列表**（表格：簇号 / 设备数 / 关联工单数 / 状态 / 最近确认时间），左栏设备注册表仍在；右侧叠一块「**今日动作**」区：已开单 3 张、回执已回写、失败 1 条（可重放）。托盘项标题带计数「2 条待处理」。底部状态栏显示「常驻运行中 · 上次拉取 12:41:03」。

关键约束：**簇数、设备数、待处理数在窗口与托盘两处当场可见** —— 不翻日志、不开终端。

## 视觉语言

| 维度 | 取值 |
|---|---|
| 主色 | 深蓝 `#1F3A5F`（设备科工位屏，专业、克制） |
| 状态色 | 绿 `#2E7D32`（已开单 / 已闭环）、橙 `#E07B00`（观察中 / 待人工判断）、红 `#C62828`（失败 / 需重放）、蓝灰 `#5A6672`（次要文字） |
| 中性底 | `#F2F4F7`（卡片底） |
| 字体族 | 正文系统无衬线（`PingFang SC` / `Microsoft YaHei`）；设备号、固件版本、时间戳用等宽（`SF Mono` / `Consolas`）便于逐位比对 |
| 信息层级 | 最显眼 = 簇卡片的「核查步骤（按优先级）」（16px 加粗）；次显眼 = 成员表格（等宽 12px）；最弱 = 状态栏与表头说明（11px 灰） |
| 留白密度 | 密而不挤：卡片内边距 16px、行高 28px，一屏最多 2 张完整簇卡片，超出滚动；数字等宽右对齐 |

## 必须可达的约束

- **托盘项计数 + 窗口内横幅 + 点击托盘唤起窗口**：用系统托盘库（`tray-icon`）实现，属可达形态。
  **不画操作系统级 toast / 气泡弹窗** —— 本形态没有该通道，凭空画出即为不可达的假画面。
- **窗口**：即时模式 GUI（`egui` / `eframe`），卡片、表格、按钮、状态栏、横幅均属其基本能力，可达。
- **核查步骤与优先级排序**：属规则 + 模型输出的结构化文本，不需要任何图形 / 动画能力。
- **曲线图、3D 场景、GPU 特效、动画转场**：一律不出现在本卡 —— 本产品画面里没有曲线，不引入图表依赖。
